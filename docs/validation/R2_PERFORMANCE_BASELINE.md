全库冷缓存最小 gate 间隔为 **1.500014 秒**，1/2/4 子样本分别为 1.500019 / 1.500078 / 1.500041 秒。真实网络轮次均没有 deferred、限流、冷却、解析失败、传输失败或缓存写入错误；所有 HTTP 返回 200，但业务响应中仍有 not_found。未自然触发重试不代表未验证重试：真实 worker 的 503/429 重试、截止和取消仍由隔离回归覆盖。

本次各网络轮次最大同时在途尝试数均为 1。全库单次尝试中位耗时 0.886076 秒、最大 1.225237 秒，均小于请求启动间隔，因此 workers=2/4 没有形成网络等待重叠。388 次请求的仅节流下限约为 `387 × 1.5 = 580.5` 秒；582.236 秒接近该下限。本次没有依据修改默认并发 2 或宣称 4 线程更快；慢网并发收益不由这个快速响应样本证明。

## 方法与复现

- 同一冻结的 388 条历史库，所有轮次从原源读取，未串联前一轮输出。默认并发一次空缓存、三次复用该缓存；固定 8 项分别 workers=1/2/4，每种使用独立空缓存。每轮新 Python 进程，避免继承内存 gate 冷却。
- 子样本为 500、550、730、241930、770720、326480、627270、15150，在测量前冻结；各并发的字段值、最终状态、字段状态与应用动作一致。
- Windows、Python 3.14.2、Node 22.19.0；requests 2.34.2、keyring 25.7.0、vdf 3.4、jsonschema 4.26.0。使用本机 HTTP 代理，直连预检失败、代理预检成功，预检不计入正式结果。环境诊断的 `network_probed=false` 仅表示诊断函数本身不探测网络，实际尝试由独立指标记录。
- 交互式桌面环境，没有隔离系统负载；冷缓存期间运行过一次约 3 秒的离线脚本自检。每种冷缓存仅测一次，不作为稳定耗时上界或统计显著加速证明。
- 外部脚本包装真实 `request_once` 与原 gate，仅记录状态和时间，不改变 URL、参数、限速、超时、重试、缓存、解析及发布逻辑。尝试数表示父进程调用真实 worker，不证明远端已收到请求；时间为父进程边界，不是精确网络发包时刻。生产审计仍不提供尝试/重试计数，不能以 cache_misses 代替。
- 第一轮中断仅留下 165 条缓存，无完整报告，已排除；正式矩阵使用新的空目录。模拟 not_found 的脚本自检也不计入性能数据。没有重新登录、读取 Steam 凭据或执行收藏写回。

[测量脚本](../../tools/benchmark_enrichment.py) 与本次外部脚本逐字节相同，SHA-256 为 `6f6e692b69af3ac8795c25d6f4c77134db7d0b5fd8e665979529099ba5095735`。[脱敏统计](../../R2_PERFORMANCE_RESULTS.json) 保存环境、源指针/库文件摘要、各轮统计与结果摘要；完整个人运行、transport 记录及逐轮 report/summary 保留本机 `outputs/r2-performance/baseline-1662c7a-retry1`。文件哈希用于一致性核对，不是独立证明测试真实性的数字签名。

在干净 checkout 中、准备相同已核验输入与网络环境后，按下列顺序执行。脚本固定使用上述 8 个 AppID，输入必须包含它们；输出应位于被 Git 排除的本地目录。不要使用 `python -O`，检查依赖正常启用的断言。复现测得的是运行时提交与网络状态，不保证与此次数值一致。

```powershell
$repo = (Get-Location).Path
$source = 'C:\path\to\library.json'
$out = 'C:\path\to\new-r2-output'
foreach ($phase in @('prepare','cold','warm1','warm2','warm3','subset1','subset2','subset4','summary')) {
    .\.venv\Scripts\python.exe -B -X utf8 tools/benchmark_enrichment.py --repo $repo --input $source --output-dir $out --phase $phase
    if ($LASTEXITCODE -ne 0) { throw "R2 phase failed: $phase" }
}
```

脚本拒绝覆盖已有轮次；失败现场应保留，不能把部分缓存冒充新冷缓存。要精确复测历史生产基线，可将脚本放在 checkout 外，并用 `--repo` 指向干净的 1662c7a；该历史提交本身尚不包含测量脚本。

## 字段覆盖与数据保护

| 字段 | 补全前 | 全库冷/暖补全后 |
|---|---|---|
| genres / categories 非空 | 各 370 | 各 376 |
| genres / categories 空或未知 | 各 18 | 各 12 |
| 多人 true / false / unknown | 125 / 245 / 18 | 128 / 248 / 12 |
| 手柄 true / false / unknown | 246 / 124 / 18 | 251 / 125 / 12 |

四个字段各有 376 项 updated、12 项 retained；updated 表示应用观察值，不代表值必然改变。实际值变化分别为 genres 6、categories 9、多人 6、手柄 8 项。6 项 not_found 加上成功响应中不足以更新的字段仍会保留旧值；缺失字段没有因此强制变成 false 或空数组。这些变化来自当次公开接口响应，不能归因为本轮新增生产修复，也不代表逐游戏能力实测。

七轮均逐项验证：成员及顺序保持 388 条、game 377 条、未知总时长 27 条；只允许 `run_id`、四个元数据字段与 `provenance.store_metadata` 改变，其余全部行字段及其他 provenance 一致。原采集审计、成员来源、许可与时长证据保持；snapshot 除新 run_id/producer 外一致。源指针及全部源文件未变，每轮全部输出 manifest 哈希通过。

27 项相关离线回归通过：HTTP 状态重试 3、审核修复 10、enrich 8、metadata 6。每轮真实产物保护检查和独立统计复核均通过。R2 没有发现需要修改生产代码的性能或保护故障。

本报告不以旧版 572.493 秒计算加速比，也不替代 R3 Windows 真实账号端到端、R4 最终候选复审与 R5 整合发布。任意网络、其他系统真人认证、全库分类准确率及自动收藏写回仍不属于本次验收结论。
